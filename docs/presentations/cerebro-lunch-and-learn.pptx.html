Core invariant

Three stores, three responsibilities

JetStream Append log for source runtime sync, replay, workflow events, and rebuild paths.
Postgres Current state for runtimes, claims, findings, evidence, reports, evaluations, and projections.
Neo4j/Aura Graph projection and query backend. Useful, but never independently authoritative.

Takeaway: graph state must be rebuildable from durable records. No fourth store, no silent fallbacks, no graph-direct writes outside approved projection paths.

Part one

Source CDK: the boundary to the outside world

What a source owns

  • Spec()
  • Check(...)
  • Discover(...)
  • Read(...) one page of events

What a source must not own

  • Persistence
  • Graph projection
  • Finding identity
  • Runtime IDs or cursor advancement policy

Part two

Runtime sync: the correctness-critical path

  • Load persisted runtime and resolve safe source configuration.
  • Start from the runtime cursor and optional checkpoint.
  • Read pages, validate emitted source events, and quarantine invalid records.
  • Append accepted events before projection.
  • Project through configured stores, then advance cursor/checkpoint progress.
The cursor is allowed to move only after accepted events have been appended and projected.

Part three

Findings: durable risk states, not raw alerts

Rule registry

Rules are discoverable and registered, not hardcoded into service orchestration.

One rule per run

Evaluation lineage, fingerprints, failures, and persisted records stay attributable.

Current-state outcome

Findings represent remediable control gaps or durable risk states.

Good findings are current, graph-anchored, actionable, and risk-composed.

Source: docs/domains/findings-platform-architecture.md 7
4
Part four

Graph safety: powerful, bounded, rebuildable

Operational rules

  • Prefer platform routes over raw Cypher.
  • Keep traversal limits small.
  • Use tenant-scoped routes and URNs.
  • Start rebuilds with dry runs.

Agent query guardrails

  • Read-only Cypher.
  • Numeric LIMIT required.
  • Tenant scope required.
  • No procedures or write tokens.
